# 05 · 业务规则矩阵

> 依据：PRD §6（业务规则权威）/ §14.2（拟定参数）· api-contract.md §2.2（错误码）· 技术方案 §3（实现口径）· 红线 1–17。
> 每张表按「条件 → 动作 → 例外 → 来源」组织。**规则原文以 PRD 为准**；本文是检索友好的整理，不发明规则。

## 1. 预约窗口与放号

| 项 | 规则 | 来源 |
|---|---|---|
| 可约日期范围 | `[今日 + 1, 今日 + 7]` 共 7 天，**不含当日**（当日号由现场 / 自助机处理） | PRD §6.1、D1 |
| 放号时刻 | 每日 **08:00** | PRD §6.1、§14.2-2 |
| 放号动作 | 为「今日 + 7」生成排班与号源，直接置「可约」 | PRD §6.1 |
| 策略开关 | `booking.release.strategy = rolling \| immediate`，默认 `rolling`；`immediate` 排班生成即可约（对比演示用） | PRD §6.1、技术方案 §1.4 |
| 幂等 | 以 `(staff_id, visit_date, period)` 唯一键保证重跑不重复生成 | PRD §6.2 |
| 补偿 | 启动时若今日批号不存在则补跑（防 08:00 整机不在导致全天缺号） | 技术方案 §3.3、红线 13 |
| 窗口外请求 | 返回 `OUT_OF_WINDOW` | 契约 §2.2 |

## 2. 支付与超时关单

| 项 | 规则 | 来源 |
|---|---|---|
| 支付时限 | **15 分钟**（`payment.expire-minutes` 可配）；`expire_time = 创建时间 + 15min` | PRD §6.6、§14.2-3 |
| 占位 key 生命周期 | `appt:slot:hold:{slotId}`，value = `registration_no`，TTL = 支付时限；释放路径统一经状态单柱，Lua 比对 value 后删除 | PRD §9.1、技术方案 §3.1 |
| 超时关单触发 | 30 秒巡检两段式：① 近过期（`expire_time ∈ [now, now+2min]`）主动向渠道查单，已支付则合成回调喂链路；② 到期（`expire_time <= now`）先查渠道确认未支付 → 关单 | 技术方案 §3.4、PRD §9.4 |
| 关单执行顺序 | 支付单置「已关闭」→ 挂号单置「已关闭」→ Slot 回补「可约」（`time_point` 已过 →「已过期」）→ 余量缓存递增 → 落台账 | 技术方案 §3.4、PRD §9.4 |
| 幂等 | 三步 CAS 均以「待支付」为条件，**CAS 条件即幂等**；关单批号落 `appt_job_log` | 技术方案 §3.4 |
| 竞态仲裁 | 回调先到 → 关单跳过；关单先到 → 回调走「钱到了号没了」：记异常 + **自动全额退 + 告警**（不是返回成功就算了） | 技术方案 §3.4、红线 7 |
| 例外 | 超时未支付**不涉及退款、不计黑名单**（未完成支付不构成违约） | PRD §7.2 注、红线 8 |

## 3. 取消 / 退号政策

| 项 | 规则 | 来源 |
|---|---|---|
| 在线退号时限 | **就诊前一日 23:00 前**；当日及以后不可在线退（到院窗口处理） | PRD §6.7、§14.2-4 |
| 可退状态 | `status = BOOKED`（已预约）；待支付状态走「取消」（B4）而非退号 | 契约 §4.4/§4.5 |
| 超时错误码 | `REFUND_DEADLINE_PASSED` / `REG_STATE_INVALID` | 契约 §2.2 |
| 回池 | Slot 行 `status` 改回「可约」（行仍在，回池天然成立）；**`time_point` 已过 → 置「已过期」** | PRD §6.7、红线 9 |
| 退款 | 已支付则生成退款单，`settle_status` 置「待退费」；退款走异步回调链路 | PRD §6.7、契约 §4.5 |
| 缓存 | 回池后余量缓存同步递增（**先 DB 后缓存**，afterCommit Lua 守卫） | PRD §6.7、红线 9 |
| 黑名单口径 | **主动退号计入**黑名单统计（半年内退号 + 爽约合计）；**停诊被动退号不计入** | PRD §6.9、契约 §4.5 |
| 待支付取消（B4） | 患者主动取消，效果同超时：三步 CAS + 台账 + 余量 +1 + 关单站内信；**不涉及退款** | 契约 §4.4 |
| 改约 | **本期不做**：退号 + 重新预约覆盖，无专门状态分支 | PRD D4、§13.2 |

## 4. 签到与爽约

| 项 | 规则 | 来源 |
|---|---|---|
| 可签到时间 | **就诊日当天 00:00 起**（放宽，避免患者提前到院无法签到） | PRD §6.8、§14.2-8 |
| 签到方式 | 患者出示就诊码（内容 = `registration_no`），分诊台扫码（E1 `sign_type=SCAN`）；手动补签（E2 `sign_type=MANUAL`） | PRD §6.8、契约 §7.1/§7.2 |
| 超时判定点 | **`time_point + 30 分钟`** 仍未签到 → 爽约 | PRD §6.8、§14.2-5 |
| 扫描调度 | 每 5 分钟；半开窗口 `[now-35min, now-30min)` 作主批处理 + **`time_point <= now-35min` 全量兜底**（半开窗口会漏判，M2/红线 13） | PRD §6.8/§9.3、技术方案 §3.3 |
| 竞争 | 签到与扫描竞争同一 CAS（`WHERE status='BOOKED'`），**先到先得** | PRD §6.8、技术方案 §3.3 |
| 补签限制 | 已判 `NOSHOW` 的单**不可补签**（爽约判定权威） | 契约 §7.2 |
| 错误码 | `SIGN_TOO_EARLY`（未到 00:00）/ `SIGN_WINDOW_CLOSED`（已过判定点或已签到） | 契约 §2.2 |
| 置完成 | 已签到且就诊日已过 → 每日 23:30 批量置「已完成」 | 技术方案 §3.3、PRD §9.3 |

## 5. 黑名单（违约记录）

| 项 | 规则 | 来源 |
|---|---|---|
| 统计口径 | **半年内退号 + 爽约合计次数**；**按账号（`user_id`）统计**（防多就诊人绕过，M13/红线 14）；**超时未支付关单不计入** | PRD §6.9、红线 8/14 |
| 阈值 | **6 次 → 限制预约半年** | PRD §6.9、§14.2-6 |
| 解除 | 到期自动解除（`end_time` 扫描）；管理员可人工提前解除 | PRD §6.9 |
| 校验位置 | **下单前置**（B1 事务内锁内精查），命中直接拒绝 → `BLACKLISTED` | PRD §6.9、契约 §2.2 |
| 停诊被动退号 | **不计爽约、不计黑名单** | PRD §6.10、红线 8 |

## 6. 限购与冲突校验

| 规则 | 条件 | 动作 / 兜底 | 来源 |
|---|---|---|---|
| 同时持有有效预约 ≤ 3 | 有效 = `WAIT_PAY / BOOKED / SIGNED`，按 `user_id` | 计数规则**无唯一索引可兜** → 挂号事务内账号行 `SELECT … FOR UPDATE` 串行化同一用户（M3）；超限 `LIMIT_HOLD_MAX` | PRD §6.5、红线 14、契约 §4.1 |
| 同一就诊人同科室同日限 1 | 按 `patient_id` | `UNIQUE(patient_id, dept_id, visit_date, active_flag)` 兜底；`LIMIT_DEPT_DAY` | PRD §6.5/§4.2-5 |
| 同一就诊人同一时间点不可挂两名医生 | 按 `patient_id`，`time_point` 为完整 datetime（跨日期不误判，D-S1-1） | `UNIQUE(patient_id, time_point, active_flag)` 兜底；`LIMIT_TIME_CONFLICT` | PRD §6.5、D-S1-1 |
| 提交幂等 | `Idempotency-Key` 请求头（缺失返回 400）；Redis 存首次结果 TTL 24h | 重复提交返回首次结果 + `DUPLICATE_SUBMIT`（**非失败语义**） | 契约 §2.5/§4.1 |
| 服务端强校验 | 不信任前端任何判断；四层 API 边界不混用 | 权限 / 归属 / 限购全部服务端判定 | 红线 10、PRD §6.5 |
| 就诊人上限 | 每账号 ≤ 10 | 超限 `PATIENT_LIMIT_EXCEEDED` | PRD §14.2-9、契约 §2.2 |

## 7. 退款规则（六场景全矩阵）

| 场景 | 是否自动退款 | 说明 | 来源 |
|---|---|---|---|
| 医生停诊（被动取消） | ✅ **自动全额退** | 患者无过错，停诊处理时批量自动发起 | PRD §6.6、红线 8 |
| 患者主动退号（时限内） | ✅ **自动全额退** | 退号成功即触发 | PRD §6.6、红线 8 |
| 患者爽约 | ❌ **不退** | 构成违约，不予退款 | PRD §6.6、红线 8 |
| 超时未支付关单 | **不涉及** | 未发生实际支付，仅关单；不计黑名单 | PRD §6.6、红线 8 |
| 对账发现的漏退款（R3） | ✅ **自动补退** | 排除「已爽约」；SQL 与处理同退号退款 | PRD §6.6/§9.6、技术方案 §3.6 |
| 重复支付 / 系统错误 | ✅ **自动全额退** | 对账或人工确认后发起；多余 trade_no 走退款单退回 | PRD §6.6、技术方案 §3.5 |

通用约束：**一律全额退，不做部分退款与手续费扣除**；`refund.auto-enabled` 可关闭自动退款改后台人工发起；失败按退避策略重试（次数可配），仍失败置「退款失败」进人工队列 + 告警（PRD §6.6、契约 §5.5）。

## 8. 停诊

| 项 | 规则 | 来源 |
|---|---|---|
| 粒度 | 单个午别（`SCHEDULE`）/ 某医生某日（`STAFF_DATE`）/ 院区某日（`CAMPUS_DATE`）；**日期区间按日拆 N 条登记，共用同一 `batch_no` 幂等归并** | PRD §6.10（本轮口径对齐）、D-S1-5 |
| 两段式 | E5 分诊台**只登记**（`status=PENDING`）→ F2 管理端**处理**（置 `HANDLED`）；入参是登记行 ID，服务端取其 `batch_no` 作幂等锚点 | 契约 §7.5/§8.3 |
| 已挂号单 | 待支付 / 已预约 → 批量「已退号（被动）」，`cancel_type=PASSIVE`，**不计爽约**；已支付则批量退款 | PRD §6.10、红线 8 |
| **已签到的单** | **不参与批量退号**（患者已在院，现场人工协调）——**状态机无对应边**（U1） | PRD §6.10/§14.3 |
| 未预约号源 | 标记「已停诊」，不可约 | PRD §6.10 |
| 通知 | 向全部受影响患者发站内信 | PRD §6.10 |
| 幂等 | 批号 + CAS 守卫；重复执行第二次全部影响 0 行（不重复退号 / 退款 / 通知） | PRD §6.10、红线 12 |
| 批量约束 | 分批事务 ≤100/批，避免长事务 | 红线 12 |

## 10. 收费

| 项 | 规则 | 来源 |
|---|---|---|
| 定价键 | `(职称 title, 门诊类型 clinic_type)`，生成 Slot 时写入 `slot.fee` | PRD §6.4 |
| 已定档位 | 主任医师 ¥22.00 / 副主任医师 ¥15.00 / 主治医师 ¥6.00 / 副主任护师（夜间）¥7.00（均虚构示例） | PRD §6.4、§14.2-12 |
| 矩阵规则 | 5 职称 × 3 门诊类型全组合；**未列组合由 seed 自定并全量落入 `appt_fee_standard`**；生成 Slot 取不到档位 → **直接报错，不静默跳过** | PRD §6.4（本轮补） |
| 快照 | 支付 / 退款一律以 `registration.fee` 快照为准；`fee_standard` 变更**不追溯**已生成号源 | 红线 5、PRD §4.2-3 |
| 唯一键 | `UNIQUE(title, clinic_type)`；停用行仍占键 → 命中停用行走「重新启用」而非 insert（否则 1062） | database-design §4/§6 |

## 11. 通知场景（七种）

挂号成功（待支付）/ 支付成功 / 超时关单 / 退号成功 / 停诊取消 / 爽约记录 / 黑名单生效，均发站内信；本期**不做**微信订阅消息。`notice.type` 线值待 S6 定义（**Q3**）。（PRD §6.12、契约 §6）

## 14. 配置开关总表（技术方案 §1.4）

| 配置 | 默认 | 说明 |
|---|---|---|
| `booking.window.days` | 7 | 可约窗口 `[今日+1, 今日+N]` |
