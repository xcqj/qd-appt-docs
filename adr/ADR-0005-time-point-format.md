# ADR-0005 `timePoint` 统一按 `HH:mm` 输出

- 状态：已采纳
- 影响面：签到（E1/E2/E3）、就诊码、分诊当日列表、后台列表与导出

## 背景

`appt_slot.time_point` 是 `time` 类型，Java 侧是 `LocalTime`。默认序列化会带秒（`HH:mm:ss`），
而移动端与分诊台只展示到分钟。前端各自 `slice(0, 5)` 的结果是：

- 三个页面三种截法（有的截字符、有的用 `substring`），一旦后端补 `@JsonFormat` 就重复处理；
- 后台导出与前端展示不一致，对账时「同一号源两个时间」；
- 契约里没写清，属于隐性口径。

## 决策

- **后端统一序列化**：`SignListVo` / `SignResultVo` 等含时刻的 VO 加
  `@JsonFormat(pattern = "HH:mm")`，接口层直接给到分钟；
- **前端不做二次截断**：拿到什么显示什么，不再 `slice`；
- 需要精确时间的场景（排班模板、时段生成）走各自的 `LocalTime` 字段，不受此约束。

## 后果

- 好处：三端一致、契约明确、少一类「看起来一样但代码不同」的重复逻辑；
- 代价：VO 级注解容易漏（新增 VO 要记得加），已在 `backend/AGENTS.md` 的实体约束里提示；
- 兼容：已有前端若仍在截断，结果为幂等（`HH:mm` 截完还是 `HH:mm`），可以安全滚动发布。

## 证据

- 进度记录：`docs/ROADMAP.md` §5「收尾两处偏差」
- 受影响页面：签到结果、就诊码、分诊当日列表（见 `app/DESIGN.md` §9.8 / §9.10 与分诊三屏）
