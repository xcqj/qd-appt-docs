# ADR-0003 `active_flag` 与唯一索引：号源不物理删除

- 状态：已采纳
- 影响面：`appt_slot` 写入与回池、唯一索引设计、对账与台账

## 背景

号源（`appt_slot`）会被占用、释放、停诊回收。若用物理删除表达「失效」：

1. **丢审计**：台账与对账需要「这个号源曾经存在过、被谁占用过」，删了就查不到；
2. **唯一索引打架**：同一 `(staff_id, visit_date, period, time_point)` 若删后重建，
   会与「同键只能有一行」的约束冲突，只能靠先删后插，容易在并发下产生间隙；
3. **回池语义不清**：到底是「新号源」还是「原号源可用」，报表会重复计数。

## 决策

- 号源行**永不物理删除**，用 `active_flag`（1 有效 / 0 失效）表达可用性；
- 唯一索引只对「有效行」生效（复合唯一键 + `active_flag`），保证同一时间点只有一个有效号源；
- 占用 / 回池 / 停诊回收都是 `UPDATE`，并写 `appt_slot_ledger` 台账（动作 + 前后状态）；
- 删除类管理操作（模板、排班）改为「删除前校验引用」：被有效挂号引用时拒绝删除。

## 后果

- 好处：台账完整、报表可回溯、并发下不会因删插产生唯一键间隙；对账七查能对齐「应有 / 实有」。
- 代价：表只增不减，需要定期归档策略（当前数据量小，未做分区）；查询必须显式带 `active_flag`，
  漏写会统计到失效号源——这条已写进 `backend/AGENTS.md` 的实体约束。
- 与停诊的配合：停诊处理只把号源置为 `active_flag = 0`，不改行数，回池数量因此可信。
